# Distribution Guide

How DiskBytes ships: what the artifacts are, what Windows will say about
them, and what to tell users (and yourself) before running an unsigned
or self-signed build.

## Artifacts (`scripts/build.ps1 -Arch x64` → `dist-release/`)

| File | What it is |
|---|---|
| `DiskBytes-<version>-x64-setup.exe` | Per-user NSIS installer (no admin needed; WebView2 bootstrapper embedded) |
| `DiskBytes-<version>-x64-portable.zip` | Bare `DiskBytes.exe` + README; runs without installing (WebView2 must already exist) |
| `SHA256SUMS.txt` | SHA-256 of every artifact (regenerated by `scripts/sign.ps1` after signing) |

Both artifacts are built by the same CI workflow (`bundle` job on
`windows-latest`) that runs the full gate battery first — the bits you
download from CI are the bits the gates verified.

## Windows permissions

- **Installer**: per-user (`installMode: currentUser`). It writes under
  `%LOCALAPPDATA%` and needs **no elevation**. The one exception: the
  optional Turbo engine requests admin (via `ShellExecuteW "runas"`) at
  scan time only, when you click Restart as administrator.
- **Portable**: no writes outside `%APPDATA%\DiskBytes` (license cache,
  snapshots, anonymous analytics id) and `%LOCALAPPDATA%\DiskBytes`.

## SmartScreen ("Windows protected your PC")

Unsigned binaries downloaded from the internet carry the Mark-of-the-Web
and Windows SmartScreen shows a warning. This is expected for private
builds. For the user flow:

1. The dialog offers **More info**.
2. Click **More info** → **Run anyway**.

For PowerShell/script use on a downloaded zip, clear the mark instead:

```powershell
Unblock-File .\DiskBytes-<version>-x64-portable.zip   # before extracting
# or, per file after extracting:
Get-ChildItem -Recurse | Unblock-File
```

Verify the download against `SHA256SUMS.txt` first:

```powershell
Get-FileHash .\DiskBytes-<version>-x64-setup.exe -Algorithm SHA256
```

## Signing (optional, for wide distribution)

`scripts/sign.ps1` signs every artifact when `signtool.exe` (Windows
SDK) and a code-signing certificate are available:

- **EV / OV cert in the certificate store**: `scripts/sign.ps1`
- **PFX file**: `scripts/sign.ps1 -CertFile .\diskbytes.pfx`

Signing + timestamping (DigiCert URL by default) builds SmartScreen
reputation over time; unsigned builds remain fine for private testing
with the Unblock flow above.

## WebView2 notes

The setup exe embeds the WebView2 bootstrapper and installs it on
first run if missing. The portable build requires an existing WebView2
runtime (present on every current Windows 10/11 by default).

## What we never ship

- No live payment keys, webhook secrets, or PostHog personal keys in
  the repo or binaries (CI greps for the patterns).
- No session recording, no autocapture, no file paths in analytics.
- No direct-delete code paths (R7.1 grep is a release gate).
